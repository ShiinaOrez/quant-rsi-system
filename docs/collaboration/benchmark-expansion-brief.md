# Benchmark 扩题任务书

状态：已由 Claude Opus 5.5 展开，Codex 核查并修改后收录为 18 道 draft 题。详见[套件说明](../benchmark/diagnostic-suite.md)与[协作审核记录](benchmark-expansion-review.toml)。以下保留选题及交付要求。

## 选题规则

现有 AAPL、INTC 两题保留。本轮增加 18 题，总计 20 题：MSFT、AMZN、META、MU、PYPL、NVDA 六只股票，分别取 2022-12-30、2023-06-30、2024-06-28 的收盘时点。每只股票使用全部三个时点，不根据后续涨跌增删窗口。

这些都是历史样本，不能据此声称排除了模型预训练记忆。六只股票也不能代表整个股票市场；本轮只扩展现有 NASDAQ 单标的环境。相同日期的题目受共同市场行情影响，统计时需要按日期和发行人分组，不能把 20 题当作 20 个独立样本。

新增题全部进入 validation。保留的 AAPL 配置虽然写着 test，也不能仅凭这个字段称为封存测试集。后续划分训练和测试集时，要先处理发行人、重叠交易窗口以及共享文档造成的泄漏。

## 六个观察方向

| 标的 | 需要展开的问题 | 需要核对的原始材料 |
| --- | --- | --- |
| MSFT | 分部收入、云业务与资本开支，利润和现金流是否给出相同判断 | 当时已发布的三张报表、分部披露、资本开支和会计估计说明 |
| AMZN | 零售与 AWS 的经营结果、营运资金、资本支出和租赁口径 | 分部经营利润、现金流调节、设备采购与融资租赁披露 |
| META | 广告经营、Reality Labs 投入和重组费用如何共同影响估值判断 | 分部结果、费用、资本开支、股票薪酬与回购披露 |
| MU | 存储周期、库存和减值，怎样区分价格变化与资产负债表压力 | 库存、减记、毛利率、资本开支及对应财季口径 |
| PYPL | 支付规模、利润率和现金质量，哪些指标不能互相替代 | TPV、交易收入和费用、信用损失、现金流及股票薪酬 |
| NVDA | 业务结构变化、库存和收入，以及拆股前后数据的一致性 | 分部收入、库存与采购承诺、应收款、拆股和分红公告 |

这是待验证的诊断方向，不是已测得的难度排名。不要把某个财报指标直接写成确定的买卖答案，也不要要求交易者提前知道财报结果。

## 题目契约

沿用 `benchmarks/environments/us-equity-daily-v1.toml`：初始现金 100000 美元，初始空仓，次交易日开盘成交，60 个交易日，不做空、不加杠杆，收益目标 5%，最大回撤上限 10%，手续费和滑点各 5 bps。新增任务保持 draft，数据 manifest 和哈希保持 UNBOUND。

任务 ID 使用 `{symbol小写}-{YYYY-MM-DD}-60d`。冬季时点是 `16:00:00-05:00`，夏季是 `16:00:00-04:00`。60 个交易日从截止日之后开始计数。不要把报告期末误当作公开日期。

任务 TOML 只使用现有严格 schema 的字段。选题依据、证据和数据构建要求另存 assessor、data-plan 或套件说明，不能塞进 agent 的观察。完整历史档案、财务报表版本、公司行动和交易数据都需要后续物化与审计；几份财报链接不能替代完整数据集。

## 交给 Claude 的详细工作

逐题给出：截止日前可以获得的官方财报来源、文档发布日期、当时需要处理的财务问题、容易混淆的口径、数据缺口，以及后续数据构建的检查项。优先使用公司投资者关系页面和 SEC 原始文件；无法确认的信息明确标为待核实。日期只有日级精度时不要补造具体发布时间，沿用下一交易日开盘可用的保守规则。

提供结构化草稿，字段应能直接转为 TOML。不要为凑齐题目编造数值、accession、链接或事件。每题至少一份截止日前的官方财报作为起始核查点，但仍须要求完整历史档案。2022 年底时不能使用次年才公布的全年报；MU 和 NVDA 的财年需要明确对应自然时间。

可以说明截止日之后逐步揭示的事件怎样检验执行规则，但必须与初始可见信息分开。优先把检查落在可观察的数据和行为上，例如读取了哪份版本、是否把调整后收盘价用于原始开盘成交、是否把不同现金流口径混合。

## 接收与修改

Codex 负责逐项打开并核对来源、检查交易日和时区、验证配置、审查未来信息泄漏，并改写最终文字。删除没有证据的难度结论、重复套话和事后解释；保留具体事实、数据限制与可执行检查。原始草稿和运行回执放在忽略的 `artifacts/collaboration/`，仓库记录实际模型、任务书哈希和采纳情况；只有成功调用并核对回执后才记录 Claude 已参与。

模型固定请求 `claude-opus-5-5`，不配置自动降级。调用只授予研究所需工具，不提供仓库推送权限；最终改动由 Codex 接收。若模型不可用或身份认证失败，记录实际阻塞，不冒充 Claude 已完成内容。
