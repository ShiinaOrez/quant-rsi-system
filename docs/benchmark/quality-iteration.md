# 20 题质量迭代协议

本轮先补齐完整档案，再运行 Qwen。范围为 `nasdaq-diagnostic-v1.toml` 中全部 20 题。现有 INTC 子集运行只验证本地资源，不计入正式套件成绩。下载失败、未执行和模型未达标是三个不同状态。

## 数据准入

每个发行人先构建可复用的档案，再按题目的 cutoff 和 60 个交易日编译环境。采集清单必须覆盖 SEC submissions 的 recent 和全部历史分片；按共享计划中的 form 过滤，并保留修订版及附件。不能把种子财报链接当成完整历史清单。文档保存原始字节、来源、检索时间、哈希、accession、accepted_at 和覆盖范围。缺失的已知 accession 或附件必须进入缺口表。

三表数字须绑定原始文档、期间、单位、维度和公开时间；重述追加版本。最新 companyfacts 只能帮助核对，不能替代历史版本。无法确认的修订关联保留未知，不猜测。所有缺口逐项披露，未达到题目既定要求的任务仍为 draft。

行情需说明供应商及授权、当前下载版本、原始成交价格的还原方式、成交量口径，以及历史公司行动和正式派息日的来源。今天下载的数据不被标注为历史当时的供应商快照。区间执行使用交易日原始价格，指标只使用截至决策时已生效的拆股。逐题核对 XNAS 交易日、半日市、时区、分红权益和支付，以及模拟器支持的公司行动。

代理须能查询截至当前决策时间的历史，而非只看到最新一份财报。查询端绑定标的与环境时钟，不能由模型扩大时间范围。未来数据和 assessor 材料不进入工具返回值。历史行情还原所用的事后拆股因子、未来公司行动清单和全档案统计属于构建元数据，不能跟随历史 bar 一起返回给模型；编译器须显式选择代理可见字段。就绪检查还须实际验证：发布前不可查、发布后可查、后来重述不改写早期读数、分页能遍历完整历史、查询与动作都能重放。

## 运行与改进

固定模型权重 digest、提示词及工具版本、采样参数、执行引擎和成本规则。R0 为补齐后的初始成绩；随后进行三次改进，各自复跑得到 R1、R2、R3，共四版成绩。每版运行全部 20 题及 cash、buy-and-hold、SMA20/60 基线，保存逐题轨迹、配置与数据哈希、失败原因和耗时。

每次将实测成绩、覆盖表和轨迹提供给本地 Claude Opus 5.5，要求从统计套利研究者的角度审查：时点是否真实、数据是否支持判断、目标是否区分能力与运气、基线是否足够、题间是否重复、评分是否可归因。此视角不代表任何真实人物的意见。

改进须指出具体证据和可验证的修复。不得提高盈利门槛制造难度，不得根据 Qwen 成绩删题、换窗口、挑选有利种子，也不得用未来结果写入交易提示。修复数据错误后须保存旧版和新版本的差异；跨版数据变化与纯评分变化分开解释。Qwen 本轮不训练，避免同时改变被测模型和试题。模型输出非法或用尽既定工具预算时，记录代理任务失败，财务收益字段保留缺失；基础设施故障先修复再重跑。不得把这些情况伪造为收益为零的已完成交易。

报告同时保留全部逐题结果、按发行人和截止日分组结果，以及运行失败项。20 题存在相关性，不能按 20 个独立样本推断显著性。三轮后仍不具备数据准入条件的题不填造正式分数。

## Claude 调度

本地订阅采用单任务串行调度。`scripts.claude_batch` 使用文件锁；每批查询 `/usage`，未知额度不派工。默认区间使用达到 65% 或周使用达到 70% 时暂停，保留后续工作的额度；每批设置 `--max-turns` 不超过 32、超时不超过 30 分钟，结束后至少间隔 300 秒，结束时再次查询。

CLI 的实际 `num_turns` 可能包含额外处理：首批传入 32，返回报告为 36，调度器会保存实际值。因此不能将该参数当作硬 token 上限。上述规则是保守的调度条件，不能替代提供方硬限额，也不能保证单批消耗不会跨过阈值。观察到消耗较大时须进一步缩小批次；遇限额等重置，不切换账号或启用付费额度。输出、检查点和交接保存在被 Git 忽略的 `artifacts/benchmark-quality/claude/`，允许从已验证的缓存继续。首次手工派工也须在结束后登记冷却时间，后续统一走调度器。
